# RGSS1/2 配置类继承兼容

某些旧脚本先用无显式父类的类保存配置常量，稍后才为同名类指定父类，例如：

```ruby
class Scene_Task
  CHANGE_PAGE_SE = "Audio/SE/Book"
end

# 其他类和初始化代码……
class Scene_Task < Scene_Base
  # 实际场景实现……
end
```

现代 Ruby 在第二个声明处抛出 `TypeError: superclass mismatch for class Scene_Task`。此处提供的是针对该配置模式的有限兼容，并不声称 Ruby 1.8 普遍允许改变既有类的父类。

## 触发时机

- 仅在 RGSS1/2 中启用；RGSS3 使用原有求值器。
- 脚本始终先以原始源码执行。不在解压、加载或正常执行前解析、重写源码。
- 仅当游戏未自行捕获的、精确类型为 `TypeError` 的 `superclass mismatch for class ...` 异常到达脚本求值器后，才调用兼容分析。游戏自己的 `rescue` 先于本兼容层生效。
- 求值期间、限当前线程的临时 `TracePoint(:raise)` 只记录异常处的 Binding 和行号，供异常发生后恢复局部变量；不修改游戏处理的异常。每次求值退出或恢复检查前均关闭观察器。

## 恢复方式与边界

使用仓库已有的 Ruby/Prism 分析异常对应的原始脚本，要求两个声明均为同一脚本内的顶层简单类名。首个类体必须非空，且仅由字符串、整数、浮点数、符号、布尔值或 nil 等字面量常量赋值组成；失败处必须是独立单行的类头，父类也必须是简单常量名。

同时核对异常位置及运行时状态：配置类必须仍直接继承 Object，且仅持有预期的字面量常量；已经实例化、派生子类、定义方法、混入或扩展模块、设置实例/类变量、冻结或持有其他状态的类均拒绝恢复。父类不得通过 autoload 获取，也不得具有自定义 inherited 回调。跨脚本、嵌套类、命名空间路径、动态父类及模糊的重复声明不在支持范围内。包含编译期 BEGIN 块或 shareable_constant_value 指令的脚本也拒绝恢复，以避免编译期副作用重复或指令语义改变；保留开头的编码与 frozen_string_literal 注释。

符合条件时，通过 Ruby 的类和常量 API 新建正确父类的类，并保留配置常量的当前值；随后使用异常位置的 Binding，从失败的类声明继续执行。恢复状态使用内部变量名，避免覆盖游戏使用的 `source`、`filename`、`error` 等局部变量。错误前的语句、别名定义、文件写入等不会重跑；后续异常保留原始文件名和行号。同一个类在单次脚本求值中至多恢复一次，成功恢复时记录日志。

旧配置类的对象身份会改变，因此脚本不应在补写父类之前缓存或传递该类对象。运行时检查不能证明所有全局变量、闭包或容器中都没有对旧类的引用，本兼容仅适用于原本作为配置容器使用的类。不对活动类做父类修改，也不操作 Ruby VM 内部结构。

不符合条件时重新抛出原异常；恢复完成后的真实脚本错误继续正常上报。游戏文件和 `$RGSS_SCRIPTS` 中的原始源码保持不变。实现不依赖 macOS API，可随现有 Ruby 绑定层在各平台编译。
